# 个人物品管理第一阶段设计

## 目标

将现有“马克笔管理系统”完整替换为个人物品管理应用，同时保留项目现有的手绘手账、纸张纹理、翻页书、便签、字体、Rough.js 边框和图表视觉风格。第一阶段聚焦物品记录、查找、维护、使用成本分析以及 CSV 数据交换，为后续个人事项模块保留扩展空间。

## 范围

第一阶段包含：

- 将 `Things.xlsx` 中“电子产品”“衣服”“宠物用品”的有效行转为应用初始数据。
- 物品的新增、查看、编辑、删除和使用次数记录。
- 按关键字、分类和信息完整度查找物品。
- 物品总览、分类统计、价值统计、近期加入和待补充信息提醒。
- CSV 导入、预览、校验、确认写入和 CSV 导出。
- 浏览器本地持久化、完整状态 JSON 备份与恢复。
- 桌面端和移动端布局、键盘操作及减少动态效果支持。

第一阶段不包含：

- 账号、云同步、多用户或服务端数据库。
- 图片文件上传和云端图片存储。
- 自动读取任意 Excel 工作簿；现有 `Things.xlsx` 仅用于生成内置初始数据。
- 美容和穿搭业务流程；这两个空工作表暂不生成记录。
- 与原马克笔业务并行运行；旧业务会被完整替换。

## 方案选择

采用“复用视觉与应用外壳，重写业务领域”的方案：

- 继续使用 React 18、TypeScript、Vite、Tailwind CSS、React Router、Recharts、Rough.js 和现有本地存储模式。
- 复用 `Book`、`BookFlipBook`、`AppLayout`、`Header`、`StickyNotes`、通用按钮、输入框、表格、模态框和图表组件。
- 将 `Marker`、`Brand`、`Series` 等领域类型替换为 `Item`、`Category` 和物品统计类型。
- 将原页面的马克笔文案、数据、API、Hook 和特性组件替换为通用物品语义，不建立旧模型适配层。

没有采用“把物品临时映射成马克笔”的方案，因为价格、颜色、库存等字段无法表达服装材质、季节、使用次数和成本，会给后续模块留下长期兼容负担。没有重新搭建 UI，因为用户明确要求视觉风格保持不变。

## 信息架构

导航沿用原有手账翻页结构，调整为：

1. 首页
2. 物品总览
3. 物品库
4. 分类管理
5. 购入记录
6. 心愿清单
7. 统计分析
8. 导出备份
9. 设置

### 首页

首页展示物品总数、已记录总价值、分类数量和信息待补充数量，并提供近期加入物品、常用分类和待补充记录。首页只呈现能帮助用户继续整理物品的信息，不增加装饰性指标。

### 物品总览

按电子产品、衣服、宠物用品等一级分类展示物品分布、已记录价值和最近更新。分类区域继续使用现有手绘图表与纸张区块，不改成现代卡片仪表盘。

### 物品库

物品库是第一阶段的核心页面，提供：

- 名称、编号、品牌和型号的即时搜索。
- 分类和信息完整度筛选。
- 全部物品列表及明确的空状态。
- 新增、查看详情、编辑和删除入口。
- “记录一次使用”操作，直接增加使用次数并刷新派生指标。

### 物品详情

详情分为通用信息、分类扩展信息和使用情况。通用信息包含编号、名称、分类、品牌、型号、价格、开始和截止时间、备注；分类扩展信息包含颜色、材质、成分和季节；使用情况包含使用次数、持有天数、平均使用频率和单次使用成本。

### 分类管理

分类管理显示分类名称、物品数量和已记录价值。第一阶段允许新增、重命名和删除空分类；已有物品的分类不能直接删除，界面会要求先迁移物品。

### 购入记录、心愿清单和统计分析

购入记录与物品建立可选关联并记录日期、金额和备注。心愿清单保留原项目的轻量本地交互，但字段改为物品名称、分类、预算和优先级。统计分析展示分类分布、价值分布和按月份新增趋势。

### 导出备份

该页面提供 CSV 导入、CSV 导出、JSON 完整备份和 JSON 恢复。CSV 用于物品数据交换；JSON 用于保留物品、分类、购入记录、心愿清单和设置的完整状态。

## 数据模型

核心模型使用明确字段而非自由格式对象，保证 CSV、筛选和统计可预测：

```ts
type Item = {
  id: string;
  name: string;
  category: string;
  brand: string;
  model: string;
  color: string;
  material: string;
  composition: string;
  season: string;
  price: number | null;
  startedAt: string;
  endedAt: string;
  useCount: number;
  notes: string;
  createdAt: string;
  updatedAt: string;
};
```

`holdingDays`、`usageFrequencyDays` 和 `costPerUse` 为派生值，不持久化为数据真相：

- 持有天数：从开始时间到截止时间；没有截止时间时计算到当天；没有开始时间时为空。
- 平均使用频率：持有天数除以使用次数；使用次数为零时为空。
- 单次使用成本：价格除以使用次数；价格为空或使用次数为零时为空。

所有日期在应用状态中使用 `YYYY-MM-DD`。金额使用数值，缺失值使用 `null`，不使用零代替未知价格。

## 初始数据转换

从 `Things.xlsx` 读取三张有效工作表：

- “电子产品”：保留手机、手表、平板、键盘、鼠标等有名称的记录。
- “衣服”：保留已命名记录；只有类别而没有名称的行以“未命名 + 类别”生成名称，例如“未命名半身裙”。
- “宠物用品”：保留自动喂食器、猫粮和猫砂记录。
- 完全空白的占位行忽略。
- 原表的“使用时间”和“单次使用成本”公式结果不作为源数据导入，由应用按统一规则重新计算。
- Excel 日期序列先还原为日历日期，再输出为 `YYYY-MM-DD`。

初始数据只在首次运行且本地没有已保存数据时加载。之后升级应用不能覆盖用户已经修改的数据。

## CSV 契约

CSV 使用逗号分隔、双引号转义和 UTF-8 编码。导出文件写入 UTF-8 BOM，确保中文 Windows Excel 直接打开时不乱码。

标准列按固定顺序输出：

```text
编号,名称,分类,品牌,型号,颜色,材质,成分,季节,价格,开始时间,截止时间,使用次数,备注,持有天数,平均使用频率（天/次）,单次使用成本
```

其中“编号”“名称”“分类”为导入必填列；其余列可以为空。三个派生列会导出供查看，但导入时忽略并重新计算。

CSV 导入流程：

1. 选择 `.csv` 文件并读取表头。
2. 校验必填列、重复列和无法识别的列。
3. 逐行解析并展示有效行、警告行和错误行数量。
4. 对重复编号提供“跳过重复项”或“更新现有项”两种明确策略，默认跳过。
5. 错误行不写入；用户确认后一次性写入其余有效行。
6. 完成后显示新增、更新、跳过和失败数量。

日期无效、价格或使用次数为负数、必填字段为空属于错误。未知附加列属于警告，不阻止导入。CSV 中的公式内容按普通文本处理，不能在应用中执行。

CSV 导出允许导出全部物品或当前筛选结果。文件名使用 `personal-items-YYYY-MM-DD.csv`。

## 状态与数据流

页面通过领域 Hook 读取本地 Store 快照，并订阅统一的数据变更事件。新增、编辑、删除、记录使用和导入操作都通过 Store 函数完成；Store 在一次操作中更新内存、写入 `localStorage` 并发送变更事件。统计结果由当前物品快照派生，不额外持久化。

本地存储使用新的版本化键名，避免误读原马克笔数据。初始化顺序为：读取新版存储；若不存在则加载个人物品初始数据。旧马克笔存储不会自动迁移为个人物品。

## 错误处理

- 存储数据损坏时不覆盖损坏内容，应用回退到初始数据并在设置页提示恢复或重置。
- CSV 文件无法读取时给出具体原因，并保持现有数据不变。
- CSV 导入在确认前不修改 Store；确认写入以单次批量操作完成。
- 删除操作必须二次确认；分类仍有关联物品时阻止删除。
- 计算结果缺少输入时显示“—”，不显示 `NaN`、`Infinity` 或虚假的零。
- 列表和统计没有数据时提供下一步操作，不展示空图表。

## 视觉与交互约束

- 现有项目的桌面、书本、纸张、翻页、便签、手绘字体、配色、圆角、阴影和 Rough.js 描边是锁定的视觉规范。
- 不引入新的现代化仪表盘风格、玻璃效果、渐变光晕或通用卡片网格。
- 新增控件必须复用现有按钮、输入、选择器、表格、模态框和图表组件的视觉语言。
- 桌面端保持翻页书体验；移动端使用同一视觉系统下的单页滚动布局，不能产生横向溢出。
- 所有交互元素具有可见键盘焦点；动态效果遵守 `prefers-reduced-motion`。

## 组件边界

- `types`：领域数据类型和 CSV 行类型。
- `data`：初始物品、版本化本地 Store 和原子更新函数。
- `lib`：日期、成本统计、筛选、CSV 解析和 CSV 序列化纯函数。
- `hooks`：订阅 Store、组合筛选条件和派生页面数据。
- `components/features/items`：物品表格、详情、表单、删除确认和记录使用。
- `components/features/import-export`：CSV 选择、预览、冲突策略和结果摘要。
- `pages`：页面编排，不承载 CSV 解析或统计规则。
- `components/Book` 与通用 UI：仅做必要的文案和路由适配，不重写视觉实现。

## 测试策略

实现遵循测试先行：

- 单元测试先覆盖日期边界、零使用次数、未知价格、筛选组合和信息完整度。
- CSV 测试覆盖中文、引号、逗号、换行、BOM、空值、重复编号、无效日期、负数和派生列忽略。
- Store 测试覆盖首次种子加载、已有数据不被覆盖、批量导入、更新和删除。
- 组件测试覆盖表单校验、删除确认、导入预览和冲突策略。
- 浏览器验证覆盖搜索筛选、添加物品、编辑物品、记录使用、CSV 导入和 CSV 导出。
- 视觉验证覆盖桌面主屏、详情/模态框、CSV 预览和移动端物品库，并与现有项目视觉规范逐项比对。

## 验收标准

- 界面不再出现马克笔领域文案或模拟数据。
- `Things.xlsx` 的有效物品在首次运行时可见，空白占位行不出现。
- 用户可以完成搜索、筛选、新增、编辑、删除、记录使用和查看派生成本。
- CSV 导入支持预览、校验和重复编号策略，失败不能破坏原数据。
- CSV 导出可在 Excel 中直接打开且中文不乱码，全部物品与筛选结果均可导出。
- JSON 完整备份和恢复继续可用。
- 生产构建、自动化测试、桌面浏览器验证和移动端视觉验证全部通过。
